# Evals wiring contract

Tiny files, explicit glue — no JSON library in the app, so nothing here is
parsed on-device yet.

## Files

- `golden.json` — 12 queries (`id` q01..q12, `query`, `lang`,
  `expect_doc_contains` anchor). Shape-gated by `run.py`.
- `corpus.json` — 52 docs (`id` int, `title`, `text`, `lang`). Ids 1..12
  mirror golden in order: each `text` is a true paraphrase of its query
  (contains its `expect_doc_contains` anchor, NOT the full query string, so
  a word-overlap cheat cannot score). Ids 13..52 are distractors spread
  across the 6 scripts + mixed — topically plausible (photos, receipts,
  notes) but verified to contain NO golden anchor substring and no full
  query string, so the ranking is non-trivial.
- `parity.py` — real-weights probe (`google/embeddinggemma-300m`); writes
  `reference_vectors.json` (verdict + all vectors + drift stats).
- `reference_vectors.json` — generated by `parity.py`, never hand-edited.
- `r_at_1.py` — meaning-only R@1 gate: real `google/embeddinggemma-300m`
  weights via sentence-transformers (CPU-only), queries prefixed exactly as
  `Embedder.QUERY_PREFIX` does, docs as `Embedder.docPrefix` does, full-dim
  cosine rank over all 52 docs (no FTS, no word backoff). Writes
  `r_at_1_report.json`. Load failure prints `SKIP <reason>`, exit 0; exit
  is nonzero only on logic failure, never on a low score.
- `r_at_1_report.json` — generated by `r_at_1.py`, never hand-edited.

## JVM wiring

- Entry point: `EvalRunner.runEval(embedder, docs, cases)`.
- `corpus.json` row → `EvalRunner.EvalDoc(id, title, text)`.
- `golden.json` row at the same position → `EvalRunner.EvalCase(query,
  expectDocId = corpus id)`.
- The runner is meaning-only (wordCoverage 0.0, `isLookup = false`) and a
  top score of 0.0 never counts as a hit (no tie-luck).
- File-driven runner (reading `evals/*.json` from the JVM) is future work;
  tests currently construct docs/cases inline.

## What `r_at_1.py` measures vs what the JVM `EvalRunner` measures

- `r_at_1.py` (Python): the **embedding space + paraphrase corpus** — real
  EmbeddingGemma weights, real cosine ranking, honest paraphrase labels.
  It does NOT execute any JVM code: no `Embedder`, no `Vectors`, no
  `Searcher` blending. Full 768d vectors (the app will store native MRL-256;
  naive-truncation drift for that is measured by `parity.py`).
- JVM `EvalRunner` (Kotlin tests): the **code path** — prefixing, truncation,
  scoring, and hit rules — using a fake backend. It proves the wiring, not
  the weights.
- The missing link is the **JVM wire-up**: real weights through `Embedder`
  via the LiteRT-LM Linux build. That awaits the Linux-capable runtime dep;
  until then the Python number is the real-space signal and the JVM tests
  are the logic signal, and neither claims to be the other.
